## 2. Controlled records-profile approval

The source review found no supported application approval command, HTTP route or UI for promoting that exact version. Archive creation requires an approved profile for the same firm and service route. ADR-0009 establishes authoritative release-store and provider-copy boundaries. The records and practice owners still own retention policy and approval authority. 1. Obtain an approved versioned policy for record class, jurisdiction, service route, retention trigger and duration, holds, amendment, disposition and custody. Confirm who may create and independently approve profiles and when a version is eligible for use. A retention or hold policy supplies no disposal authority by implication.
2. Reuse the existing profile command and add a controlled review and approval action for one immutable firm/profile/version basis. Enforce current firm-wide authority and the approved independence rule in the application. Record actor, approved basis and timestamp and preserve the versions already bound to archives. Use an additive migration only if evidence storage requires it.
3. Connect the existing records API and staff UI to that owner. Display the exact reviewed basis and a server-derived approval affordance. Keep tenant permissions, provider retention, protection and external effects on their separately authorized paths.

**Pass when** a supported create produces an unapproved profile, an eligible independent reviewer approves exactly that version, and exact retry produces no extra approval. Wrong firm, engagement-only authority, self-approval where prohibited, stale basis and disallowed route or version cannot approve or create an archive. An existing archive continues to resolve its retained version. Use focused PostgreSQL approval/denial and archive binding checks, OpenAPI verification, and a native create-to-review smoke.
