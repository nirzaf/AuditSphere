# Purview provider integration — out of scope

The repository owner excluded Microsoft Purview provider integration from AuditSphereOps. This page remains at its existing Wiki URL so older links lead to the current scope decision, not obsolete setup instructions. Do not treat Purview tenant configuration or provider acceptance as a deployment prerequisite.

AuditSphereOps preserves exact uploaded signed-document bytes, SHA-256 identities, human decisions, and release/archive manifests. It does not claim that a Purview label, record lock, retention policy, or eSignature provider accepted an action. For current deployment prerequisites, follow the [Production Configuration Guide](auditsphere-deployment-guide-production-current.md), [Production SharePoint Configuration](auditsphere-m365-sharepoint-runbook-current.md), and [Production Readiness Checklist](auditsphere-deployment-readiness-checklist-current.md). The [current requirements](https://github.com/nirzaf/AuditSphere/blob/master/docs/auditsphere-accounting-module-requirements-current.md), the [implementation architecture](https://github.com/nirzaf/AuditSphere/blob/master/docs/architecture/auditsphere-architecture-current-architecture.md), and the [execution ledger](https://github.com/nirzaf/AuditSphere/blob/13f31321d9abc270703a3d6ac74a2ffe30b2efc3/docs/execution/status.json) govern implementation and evidence.
